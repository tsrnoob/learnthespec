What one task is

A task is a repository with one weakness in it. The grader runs the exploit inputs and the legitimate cases, so a patch either closes the hole and keeps the code working, or scores nothing.3

CWE — Common Weakness Enumeration, MITRE's catalogue of software weakness types. The public set covers 91 of them across 100 tasks in eight languages.2

Go carries more than a quarter of the set on its own.3

One attempt, and four

Every model gets four tries at each task. The two columns answer different questions, and the distance between them is not the same for every row.1

pass@1 — the mean reward over all 400 trials, which is 100 tasks at four attempts each. pass@4 is the share of tasks solved at least once in those four.12

A second chance buys the cheaper rows more than it buys the dear ones. The order below the top four is not the order of the column beside it.1

What an attempt costs

List price does not tell you what one fix costs. A model that thinks longer spends more on the same repository.1

Rollout — one agent run at one task. The board gives each rollout a one-hour time limit and counts a timeout as a failure rather than a void trial.1

The money spread is far wider than the score spread. The cheapest row on the board still closes more than half the set.1

Where the cost figure comes from

Two of the three figure columns are measured the same way for every row. The money column is not.1

Four rows are what the harness recorded while it ran. The other nine are a list price applied to a token count, and the price has a date on it.1

Two of those nine are Gemini rows, and Google's own page dates a rise on one of them.8

Which one to pick

There is no single winner. The right model depends on whether you are paying per attempt or reading the patch afterwards.
