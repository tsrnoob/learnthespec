Price per million tokens

Every vendor bills the same way. You pay per token, and input and output are priced separately.

Token — the unit of text a model reads and writes. One token runs about three to four English characters.14 Input tokens are what you send. Output tokens are what the model returns. Output always costs more, between three and six times more across this table.

The spread is wide. GPT-6 Astra output costs over twelve times DeepSeek's peak rate, and over twenty-five times its off-peak rate.

Cost per task

List price does not tell you what a job costs. A model that thinks longer burns more tokens on the same question, so a cheap rate can produce an expensive bill.

Cost per task — the API spend to complete one average task from the benchmark suite. It folds the price, the reasoning tokens and the answer tokens into a single number.2

The ranking changes completely. Claude Fable 5.1 costs eighteen times what DeepSeek costs to do the same work, for fifteen more points of intelligence.

Token efficiency

Two models can reach the same answer and spend very different amounts of text getting there. That difference is what you pay for.

Token efficiency — the total output tokens a model generates to finish the whole benchmark suite. Lower means it reaches answers with less writing. The median across comparable models is 79M.2

GPT-6 Astra is the efficient one. It finishes the suite on 49M tokens. Claude Fable 5.1 needs 160M, more than three times as many, and buys two extra index points with them.

Speed

Speed matters when you are waiting on a reply rather than running a batch job overnight.

Output speed — tokens produced per second once the model starts writing. The median across comparable models is 73.5 per second.2

GPT-6 Astra clears that median at 87.5. Every other flagship here sits below it. Grok 4.6 runs 65.0, Claude Fable 5.1 runs 68.7, Claude Opus 5 runs 59.1, DeepSeek V4 Pro runs 70.3, and Kimi K3 runs 39.6.35678 Heavy reasoning costs latency across the board.

Context window

Six of the seven hold one million tokens. Grok 4.6 holds half that.

Context window — how much text the model can hold in mind at once, counting your input and its own output together. One million tokens is roughly 1,500 A4 pages.3

Context is no longer a differentiator at the top end. It was in 2025. It is not now.

What each one can do on your machine

Benchmarks measure answers. Most real work needs the model to take actions: open files, run commands, use tools. This is where the seven separate hardest.

Agentic — the model does not only reply, it acts. It reads and edits files, runs shell commands, and calls external tools. MCP, the Model Context Protocol, is the open standard for connecting these tools to data sources such as Drive, Jira or Slack.15

Anthropic ships the deepest local integration. Claude Code “reads your codebase, edits files, runs commands, and integrates with your development tools”, and runs in the terminal, an IDE, a desktop app and the browser.15 It works on your real filesystem, not a copy.

OpenAI's Codex CLI does the same job with permissions at the centre. It lets you “inspect code, make changes, run commands” from the terminal, and exposes a /permissions command plus a visible sandbox and writable roots you can check before each run.16

Google's tool is now Antigravity CLI, run as agy, replacing the earlier Gemini CLI. It reads the workspace, proposes a plan, and asks you to confirm workspace trust before it indexes anything.17

Open weights

Two of the seven let you download the model and run it yourself. That changes the cost structure and removes the vendor from the loop entirely.

Open weights — the trained model file is published, so you can run it on your own hardware. No API fee, no rate limit, no data leaving your network. You pay for the machine instead.

Kimi K3 and DeepSeek V4 Pro both publish weights on Hugging Face, DeepSeek under the MIT licence.67 Kimi K3 scores seven points below the overall leader. That is still the highest score available to anyone willing to host it themselves.
