What Hardware Runs Which Local Model, September 2026

One rule decides everything: the model file has to fit in memory. Here are the published download sizes at every compression level, the memory in real graphics cards and Macs, and which combinations actually work.
Tsrnoob 4 SEPTEMBER 2026 COMPILED FROM 10 SOURCES CHECKED 4 SEP 2026

The rule

Ollama states it plainly in its own documentation.

“If the model will entirely fit on any single GPU, Ollama will load the model on that GPU… If the model does not fit entirely on one GPU, then it will be spread across all the available GPUs.”1

So the question is arithmetic. Download size against memory. Everything below is those two numbers.

What compression does to the file

The same model ships at several sizes. Fewer bits per weight means a smaller file and a less accurate model.

Quantisation — storing weights at lower precision to cut memory. fp16 is half precision, q8_0 is 8-bit, q4_K_M is 4-bit. The published sizes below show the effect directly: 8-bit lands near half of fp16, and 4-bit near a third.2

ONE MODEL FAMILY, EIGHT SIZES, THREE COMPRESSION LEVELS. THE 8B AT 4-BIT IS 5.2 GB; THE SAME MODEL AT FP16 IS 16 GB. THE CHOICE OF QUANTISATION MATTERS AS MUCH AS THE CHOICE OF MODEL.

Mixture of experts does not shrink the file

Qwen3's 30B model activates only 3 billion parameters per token. It still downloads at 19 GB, essentially the same as the dense 32B at 20 GB.3

Activation decides compute per token. Storage is decided by the whole model. Both have to be in memory.

The file is not the whole bill

Context costs memory too, and it scales with how much you run at once.

Context length — how much text the model holds during a conversation. Ollama documents that “required RAM will scale by OLLAMA_NUM_PARALLEL * OLLAMA_CONTEXT_LENGTH”, and that four parallel requests at a 2K context behave like an 8K context with the memory to match.1

A 9.3 GB model does not fit comfortably in 12 GB once a long context is loaded. Leave headroom.

Apple counts differently

Macs share one pool between CPU and GPU, so the ceiling is the whole machine's memory rather than a separate card.

The frontier models still do not fit

Kimi K3 is 2.8 trillion parameters and DeepSeek V4 Pro is 1.6 trillion.8 Qwen3's 235B already needs 142 GB at 4-bit.3

Nothing on a desk runs the top open-weight models at full size. The gap between what you can download and what you can load is the real constraint on local AI.

One exception is published. OpenAI states gpt-oss-120b is designed to “fit into a single 80GB GPU”, and its Ollama build is 65 GB.910
