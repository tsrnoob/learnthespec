Best AI for Coding, September 2026

Two benchmarks measure coding models, and they disagree. Here is what each one tests, what the models score, what a finished task costs, and why the tool you run the model in changes the result.

SWE-bench Verified

The older and more widely quoted of the two. It is close to saturated at the top.

SWE-bench Verified — 500 real GitHub issues, filtered by human annotators so that each one has a clear problem description, a correct test patch and a solvable fix. A model scores by producing a patch that passes the repository's own tests.1

The top three sit within one point of each other. Below them the field spreads out by thirty.

Terminal-Bench 4.0

The newer benchmark, and the closer match to how people actually use these models. It scores the model and the tool it runs in as one unit.

Terminal-Bench — 66 tasks run in a real terminal with no graphical interface. The agent must write and debug code, configure environments and recover from its own failures. Scores carry a margin reflecting run-to-run variance.4

Agent — the harness the model runs inside. It handles the loop: reading files, deciding the next command, feeding results back. The same model scores differently in different harnesses, so the leaderboard names both.

The top two are a statistical tie. GPT-6 Astra scores 58.2% and Claude Fable 5.1 scores 57.9%, and their error margins overlap.

Why the two disagree

SWE-bench gives the model a described issue and a repository. Terminal-Bench gives it a machine and a goal.

The first rewards patch accuracy. The second rewards recovery from failure, environment setup, and knowing which command to run next. A model can be excellent at one and ordinary at the other.

Claude Opus 5 resolves 96% on SWE-bench and 51.8% on Terminal-Bench.24 Both figures are correct. They measure different jobs.

Price per million tokens

Coding burns output tokens. Long files, full diffs, repeated retries.

Input tokens are the code and instructions you send. Output tokens are the patches, explanations and commands the model writes back, and they cost two to five times more. One token runs about three to four characters of English.

Cost per finished task

Rate per token does not predict the bill. A model that retries more spends more.

Cost per task — the API spend to complete one average task from Artificial Analysis's benchmark suite, combining input, reasoning and answer tokens into one figure.6

Claude Fable 5.1 costs about four times what Kimi K3 costs per task, and about eighteen times DeepSeek.

The tool you run it in

Terminal-Bench scores model and agent together because the harness does real work. Each vendor ships one, and they take different positions on how much access to grant.

MCP, the Model Context Protocol, is the open standard for connecting these tools to outside data sources such as Drive, Jira or Slack.14

Claude Code “reads your codebase, edits files, runs commands, and integrates with your development tools”, across terminal, IDE, desktop app and browser.14 Codex CLI covers the same ground with permissions in front: a /permissions command, plus a sandbox and writable roots you inspect before each run.15 Google's Antigravity CLI, run as agy, reads the workspace and proposes a plan, and asks you to confirm workspace trust before indexing.16

Open weights for coding

Three coding-capable models publish their weights. That removes the API bill and keeps source code on your own hardware.

Open weights — the trained model file is downloadable, so you can run it on your own machines. No per-token fee, no rate limit, and no code leaving your network. You pay for hardware instead.

Kimi K2.7 Code publishes under a modified MIT licence and runs a 262K context. DeepSeek V4 Pro publishes under MIT and scores 80.6% on SWE-bench Verified, within five points of GPT-5.3 Codex.213 GLM-5.3 is the only open-weight model on the Terminal-Bench 4.0 top five.4
